# EasyWar 游戏设计文档（GDD）v1

> 状态：已与玩法决策者逐条确认（2026-08-04）。
> 本文档是玩法的唯一事实来源；数值见 `docs/BALANCE.md`，计划见 `docs/ROADMAP.md`。

## 1. 定位与模式

- 即时策略占地游戏，原型参考「学科对抗赛」。
- 当前提供成熟的 **1v1**（玩家 vs 1 个 AI）与首张 **3 人混战**原型（玩家 vs 2 个 AI）；架构继续按 **1~6 个阵营**可配置，随地图规模决定上场阵营数。
- 单局目标时长 **5~10 分钟**；**无平局、无时间上限**。

## 2. 地图

- **正方形网格，四向连通**（上下左右）。
- 首版 **H 型地图（v2 链条式）**：14×13，左右两条竖链 + 中间一条横链，全部为 1 格宽链条（参考原型游戏的布局形态）。
- **6 个据点**：玩家=语文（左下），AI=数学（右上），中立要塞=化学（左上）、音乐（右下）、物理（横梁左）、地理（横梁右）。
- 格子类型（**v2 起没有"普通中立地块"，每个可进入格都归属某个据点**）：
  - **据点**：产兵、可被占领、是兵力唯一来源。
  - **关联地块（知识点）**：绑定某个据点，占领后为该据点提升产能。
- 防御值集中在 **21~24**（固定种子生成，180° 旋转对称成对赋值）。
- 视觉：**未占领 = 灰底；据点与关联地块的边框始终使用学科色表达区域关系；占领后的内部填充使用阵营色**。玩家阵营固定为蓝色，不随开局学科改变；当前选中据点使用独立的高对比宽边框。

## 3. 兵力与行军

### 3.1 生产

- **兵力唯一来源是据点产能**。
- 据点产能 = 基础产能 + 每块已占领关联地块 × 0.2 兵/秒。
- 中立据点按自身基础产能恢复驻军，但只恢复到地图声明的初始驻军；默认即 `2.5 兵/秒`、上限 40。该恢复是防御回补，不会突破初始值形成额外经济。
- **驻军上限 = 80 + 每块已占领关联地块 × 10**；**上限只约束生产**：驻军达到上限后停产，但增援/回家/据点碰撞并入的兵力可无限叠加（超出部分不损失）；丢失地块导致上限下降时存量同样保留。

### 3.2 派兵与兵流

- 操作：桌面端先**点击己方据点**，再点击目标格（地块/敌方据点/己方据点均可），建立**持续兵流**；触屏端保留从据点拖到目标格的手势。
- 节奏：**固定每 0.2 秒出一队**，每波都按源据点当前驻军动态计算理论兵力。驻军不超过 120 时为 `3 + max(0, 当前驻军 - 40) ÷ 40`；超过 120 后改为 `5 + sqrt((当前驻军 - 120) ÷ 40)`，避免超上限驻军获得过高的瞬时吞吐。每条兵流独立累计理论值的小数部分，实际出兵向下取整（例如理论值持续为 3.5 时依次派出 3、4、3、4）；实际兵力不超过源据点当前整数驻军，不足 3 时有多少派多少。
- 动态波次对玩家、AI、进攻和支援使用同一公式，不读取目标归属。友方据点双向支援时，高驻军方的净输出更大，双方会自然趋同；40 兵以内固定为每波 3 兵，是允许保留兵力差的均衡死区。敌对兵流仍按 1:1 抵扣，强方的幸存者继续推进。
- **一旦驻军被抽到 0，兵流立刻终止**（途中兵回家，需重新派兵建立兵流），后续生产或增援不会自动恢复。改道会创建新兵流，小数累计从 0 重新开始。
- 小队移速与行军数值见 BALANCE.md。
- 路径：**纯最短路径（BFS 按格数）**，不做代价权重；等长最短路有多条时优先走己方/友方格子（仅为平局打破规则）。
- **据点碰撞（枢纽规则）**：小队进入**己方据点**时直接并入驻军（无论是否为兵流终点），超出上限部分损失。由此形成"前哨后勤"玩法：远征兵流会被中途的己方据点截留，进攻必须逐段推进——先拿前哨，再从前哨出发。敌方/中立据点按双向抵扣正常战斗。

### 3.3 战斗结算（统一规则）

- **一切战斗都是双向抵扣**：双方数值互减 min(a, b)，归零方消亡，剩余方继续。
  - 小队 vs 地块防御：地块归零 → 被小队归属方占领；小队归零 → 全灭；有剩 → 继续前进。
  - 小队 vs 敌对小队（同格相遇）：互灭，剩者前进。
  - 小队 vs 敌方据点驻军：互抵；驻军归零 → 据点易主。
- 被占领的地块随后**缓慢回防**至初始上限；中立地块同样随时间回防（无人区缓慢重新武装）。
- AI 判断一次进攻是否可行时使用与权威模拟相同的恢复、生产、动态波次和路径数据。连续近似下，目标当前防御为 `H`、恢复为 `r`、到达速度为 `q` 时，需要累计到达 `H×q÷(q-r)`；若 `q≤r` 则持续兵流无法击穿。实际判断还会加入行军期间恢复、沿途非己方格、在途友军/敌军和中间据点截留，并在整段不可承受时只推进到最近前沿格。

### 3.4 兵流终止规则

| 目标类型 | 结果 |
|---|---|
| 中立/敌方地块 | 被占领 → 停止出兵；**在途小队继续飞到目标完成战斗，幸存者再走回源据点**（不原地掉头） |
| 敌方据点 | 占领后兵流**继续输送**（自动转为增援），直到玩家手动改派/停止 |
| 己方据点 | 增援流，持续输送直到手动停止/改派 |

- 同一据点重新选择并指定新目标 = 旧兵流**改道**（途中兵掉头前往新目标）。
- 桌面端单选正在出兵的据点后再次点击它自身（触屏端拖到自身）= 停止出兵；在途小队同样**到目标后再回家**。
- **兵流停止条件（对所有目标类型一致，仅两条）**：① 目标是地块且已被本方占领 → 终止；② 源据点驻军被抽到 0 → 立即终止（在途小队到目标后再回家）。**目标是据点则永不因占领而终止**：打下来之后自动变为增援流继续输送，直到驻军归零。

## 4. 关联地块（知识点）

- 每块关联地块在**地图数据里写死归属某个据点**。
- **归属方占领** → 该据点产能增加固定值。
- **敌方占领** → 归属方失去加成（削弱），**敌方不获得加成**（仅作路障）。
- 由此形成地图上的「必争之地」与「骚扰断加成」战术。

## 5. 操作与交互

### 5.1 桌面端

| 操作 | 效果 |
|---|---|
| 点击己方据点，再点击目标格 | 建立/维持兵流；命令下达后清除选择 |
| 同一据点重新选择后点击新目标 | 兵流改道，途中兵掉头 |
| 单选正在出兵的据点，再次点击它自身 | 停止出兵，途中兵回家 |
| 点击己方其他据点作为目标 | 建立增援流 |
| 鼠标拖框 | 替换为框内多个己方据点 |
| Shift + 点击 / Shift + 拖框 | 增减或追加多个己方据点 |
| 右键 / Esc | 取消当前选择 |
| 点击任意阵营的据点 | 查看当前兵力、实时产兵/恢复速度、驻军上限和已占关联地；只有己方据点会进入出兵源选择 |

多选据点下达命令时按格子索引稳定排序，避免集合遍历顺序改变兵流建立顺序。若目标也是被框选的据点，该据点自身不会向自身出兵，其余选中据点会向它增援。

据点格内只显示学科名称与当前兵力；产兵速度和驻军上限统一放在选中详情栏，避免小尺寸节点内信息拥挤。选中标记使用紧贴格子的四角标记，不遮挡相邻格。

### 5.2 触屏端预留

触屏模式保留原有“从己方据点拖到目标格”的派兵方式以及拖框/多选状态机，当前可用 `EASYWAR_INPUT=touch` 在桌面环境测试。手机端尚未正式适配触摸事件、手势冲突和小屏布局，因此不作为当前 PC 版本默认交互。

- 平台：桌面原生（macOS）优先，PC 默认点击/框选；拖拽派兵作为未来触屏模式保留。

## 6. AI

- **规则驱动三档（简单/中等/困难）+ 开发模型“神经模型 V5～V11”，全部不作弊**（不修改产能等数值，只通过玩家可见观察提交玩家级合法动作）。
- AI 选择进攻出发点时，优先使用途中不会经过己方据点、且离目标更近的前线据点，避免兵流被己方枢纽截留。若前线兵力不足，后方据点会先把兵力分段补到低于 80% 容量的前哨，再由前哨发起进攻；安全前哨达到该水位后主动停流并释放兵流名额。受威胁据点仍以 40% 容量作为防守增援停止线；玩家命令只按通用终止规则处理。
- 决策循环：每 N 秒扫描一次，按优先级执行第一个可行动作：
  1. **守**：己方据点被攻击且驻军不足 → 倾巢反击/回防。
  2. **吃产能**：有未占领的己方关联地块且驻军 ≥ 目标防御 × 阈值 → 出兵占领。
  3. **扩张**：关联地块吃满 → 啃中立要塞 / 抢玩家手上的关联地块。
  4. **总攻**：估算总兵力优势超过玩家一定倍数 → 直捣玩家据点。

| 行为参数 | 简单 | 中等 | 困难 |
|---|---|---|---|
| 决策间隔 | 3 秒 | 2 秒 | 1 秒 |
| 出手阈值（驻军 > 目标防御 × N） | 2.0 | 1.5 | 1.2 |
| 扩张野心 | 仅己方关联地块 | 会啃要塞 | 会抢玩家手上的关联地块 |
| 拦截兵流（朝对方兵流路径中途派兵对冲） | 否 | 否 | 是 |
| 同时维持兵流数 | 1 | 2 | 3 |
| 总攻阈值（兵力优势倍数） | 1.8× | 1.3× | 1.15× |
| 失误率（发呆/选次优目标） | 20% | 5% | 0% |

- **神经网络 AI 已接入游戏**：Python/PyTorch 使用玩家可见观察与玩家级合法动作训练，检查点导出为自描述内嵌权重，由 Rust 原生执行两层卷积与动作头。游戏菜单与快捷键 `4`～`9`、`0` 分别选择 V5、V6、V7·战术实验、V8·强化实验、V9·蓄兵实验、V10·长程实验、V11·自博弈，用于开发期同场对比。V5/V6 保持原 17 通道与旧合法动作口径；V7～V11 使用 22 通道、全局上下文和动态成本战术掩码。V11 不读取规则老师动作，只从冻结历史联盟的大量终局胜负学习，并以固定种子的温度 0.5 采样执行；它在双线梯形、编织双环和通过独立 hard 留出验证的外环横梁启用，旧模型的地图支持和确定性动作保持不变。Rust/PyTorch 在固定真实观察上 logits 与动作一致，模型动作仍经过统一意图队列。训练胜率不作为地图平衡或趣味性的单独证据。

## 7. 题材包装

- **学科是地图地理，不是玩家皮肤**：地图上每个据点本身就是一门学科（中立要塞也是学科据点），其关联地块就是该学科的知识点。据点被占领后**名称和学科色边框不变**（仍叫「化学」），内部的阵营色填充表达当前归属，产能与知识点加成归新主人。
- 学科池 20 门：语文（红）、数学（蓝）、英语（橙）、物理（紫）、化学（绿）、生物（草绿）、历史（棕）、地理（黄）、政治（品红）、体育（朱红）、美术（玫红）、音乐（青）、信息（青蓝）、天文（靛蓝）、哲学（金）、心理（紫罗兰）、经济（墨绿）、医学（酒红）、法学（藏青）、工程（橄榄）。开局按地图规模选取上场学科。
- **知识点名称 1~4 个字，以 2 字为主**（放开字数只是给词少的学科兜底，非必要不用 3~4 字）。
- 关联地块的知识点名称**每局进地图时从词库随机抽取**（同一据点内不重复），不再按固定索引编排；每门词库 24 词。
- 学科**只影响视觉**（颜色 + 文本词库），机制完全对称；不做学科差异技能。
- 词库为纯数据文件：`assets/subjects/*.toml`。

## 8. 技术架构

- **Rust + Bevy**，桌面原生优先（macOS），**不使用原生平台专属 API**，WASM / 手机端只留门、首版不做。
- 地图与词库使用 **TOML** 数据文件，`serde` + 自定义 AssetLoader 加载，开发期支持热重载。
- 逻辑层为独立模块（不依赖渲染），可无头运行——同时服务于 AI 模拟与未来 RL。
- 代码未开始前，文档与数据文件先行（本目录 + `assets/`）。
