# EasyWar 地图设计

把地图视为“格子图 + 据点图”，先设计战略选择，再落格和写 TOML。不要用视觉对称代替战略公平，也不要用 AI 胜率代替真人体验。

## 1. 先读取项目事实

开始任何地图工作前：

1. 定位仓库根目录。
2. 完整读取 `docs/MAP_GUIDE.md`，把它作为地图规则和阈值的唯一权威来源。
3. 涉及玩法语义时读取 `docs/GDD.md`；涉及驻军、生产、防御或局时数值时读取 `docs/BALANCE.md`。
4. 涉及 TOML 时读取 `crates/logic/src/map.rs` 以及至少一张同模式的现有地图。
5. 涉及验证时读取 `crates/logic/tests/map_candidates.rs` 和 `crates/logic/src/bin/selfplay.rs`，确认工具当前支持的模式与对称方式。

若文档、加载器和现有地图冲突，以可执行加载器和测试揭示冲突，先向用户说明，不要静默猜测。

## 2. 按任务类型行动

- **讨论或构思**：先给出体验命题、据点骨架、路线角色与取舍；用户未选定方向时，不急着写 TOML。
- **创建或修改**：完成据点骨架、正交落格、TOML、静态验证和适量动态验证。
- **评审或诊断**：默认只读，输出硬约束、拓扑风险、支配路线、公平性和验证缺口；除非用户要求，否则不改文件。
- **制作标准调整**：把可复用结论更新到 `docs/MAP_GUIDE.md`，不要只留在对话或单张地图注释里。

## 3. 冻结玩法边界

地图任务默认只调整拓扑、据点数量、区域形状、关联地块和地图初始数据。不要顺带修改交互、生产公式、移动、战斗或 AI 行为，除非用户明确授权。

以下约束始终执行：

- 只允许上下左右四邻接，不允许对角连接。
- 所有可进入格必须属于同一连通分量。
- 每个非据点可进入格必须且只能关联一个据点；禁止无关联普通地块。
- 每个据点必须拥有 `1..=10` 块关联地块；禁止 0 关联据点。
- 当前单屏地图原则上不超过 `17×13`；超出前先解决客户端显示能力并取得用户同意。
- 正交落格后必须从真实四邻接重新推导据点图，拒绝意外接触和漏接。
- 据点总数、据点度数和环数不设机械上限；每个新增节点或边都必须增加可解释的决策。
- 允许受控环路；主力地图不要退化成单割点或唯一中央必经点。
- 不允许一条路线同时更短、更便宜、经济更多且更安全。

## 4. 先设计据点图

按以下顺序设计，不要直接随机铺格子：

1. 写一句体验命题，例如“短压制线与长经济线之间存在有成本换线”。
2. 选择经过验证的母版并做参数化变体；不要无约束随机连边。
3. 画据点骨架，标记出生、进攻、经济、换线和混合枢纽。
4. 解释每条路线的速度、收益、风险与反制方式。
5. 检查落后方丢掉一线后是否仍能施压或换线。
6. 再在 `17×13` 内正交落格，以一格宽走廊为主，据点附近允许局部宽区。
7. 切分区域归属，加入必要的经济叶子、主干地块和侧向接口。

关联地块数量由地图作用决定，不固定每座据点相同；但对称角色必须拥有等价的地块数、初始驻军、防御成本和机会集合。

## 5. 按对局模式验证公平

### 1v1

- 要求存在交换两名玩家出生位的带标签自同构；几何可以不镜像，但战略角色与成本必须等价。
- 双方出生据点之间至少有两条内部据点互不重合的路线。
- 教学图或明确“争中”的特殊图可以例外，但必须单独标注，不能伪装成主力图。
- 检查双方到各类中立据点的路径长度、防御成本、经济容量和换线机会是否一一对应。

### 3 人及以上

- 不套用 1v1 左右镜像标准；要求所有出生位在带数值的据点图上属于同一个自同构轨道。
- 比较每个出生位到其他玩家的距离集合、到各类中立目标的机会集合、初始经济和可选开局。
- 评审夹击、坐收渔利、领先者牵制、淘汰后的残局收束。
- 当前 3 人动态评估器尚未完成。不要复用 1v1 自对局并宣称多人平衡通过；只报告已完成的静态验证和真人试玩证据。

## 6. 写 TOML 与静态校验

创建候选地图时：

1. 复用同模式地图的字段结构和当前冻结数值。
2. 为对称格使用可复现的防御种子或显式等价值。
3. 把新的 1v1 候选加入 `crates/logic/tests/map_candidates.rs` 的候选集合；为多人图补充对应模式的专用断言。
4. 至少验证：尺寸、完整覆盖、`1..=10` 关联地块、无 `Plain`、连通、玩家对称、路线冗余和镜像防御值。
5. 运行：

```bash
cargo test -p easywar-logic --test map_candidates
cargo test --workspace
```

`tools/map_topo/analyze_maps.py` 目前分析评审 HTML 且依赖 `networkx`，不是 TOML 静态校验的唯一真相。依赖不可用时不要临时污染项目环境；优先使用 Rust 加载器与测试，确需该分析器时先说明依赖方案。

## 7. 动态筛选

对受支持的纵向对称 1v1 地图运行：

```bash
cargo run -q -p easywar-logic --bin selfplay -- 10 600 <map.toml>
```

正式筛选再按 `docs/MAP_GUIDE.md` 扩大样本。必须分别报告左右座位、阵营编号、意图提交顺序、超时率和完赛均时。

注意：当前自对局只正确处理它明确支持的对称方式，并存在 AI 与同帧意图顺序偏差。若地图不是纵向镜像 1v1，先扩展评估器；不要强行解释现有结果。AI 仅用于发现收束、扫描顺序和明显节奏问题，最终平衡必须经过真人试玩。

## 8. 交付格式

每次地图工作至少交付：

- 体验命题和路线角色；
- 据点图与真实落格后的拓扑差异；
- 尺寸、据点数、地块范围、环秩、割点/桥和独立路线；
- 玩家公平性证据；
- 静态测试结果；
- 自对局结果及其适用性限制；
- 真人试玩顺序和需要观察的问题；
- 对 `docs/MAP_GUIDE.md` 的新增结论，若没有则明确说明无需更新。

发现硬约束失败时停止候选晋级，先修图再谈数值平衡。
